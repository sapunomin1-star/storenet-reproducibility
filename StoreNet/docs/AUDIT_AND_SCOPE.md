# 稽核結果與可復現邊界

稽核日期：2026-08-31  
資料版本：Figshare collection v1，DOI `10.6084/m9.figshare.c.6829134.v1`  
資料論文：Trivedi et al., *Scientific Data* (2024), DOI `10.1038/s41597-024-03454-2`
方法論文：Bahloul et al., *IEEE TSTE* (2022), DOI `10.1109/TSTE.2022.3187217`

## 最終判斷

Claude Code 原先提出的「先資料理解、再完整復現、最後改進」順序正確，但現有文件與三支 Python 程式不能直接當成復現實作。最關鍵的修正如下。

| 原先主張或做法 | 稽核結果 | 本專案處置 |
|---|---|---|
| `data/raw` 是原始感測資料 | 錯。它是作者已改名、重採樣並部分線性插值的 Figshare 發布版 | 目錄保留不改名以免破壞路徑，但所有文件與程式標記為 `processed release` |
| 第二篇直接使用第一篇公開資料 | 只對同一專案，不對公開版本。VPP 論文早於資料論文兩年 | 稱為同源獨立復現，不宣稱精確重現原數值 |
| `prep_30min.py` 可作正式資料管線 | 錯。它會把缺資料與 H14 檔尾靜默補成 0 | 新管線禁止靜默補零，保留品質遮罩並在超過門檻時拒絕求解 |
| 能量平衡 99.9% 通過 | 錯。納入 Feed-in 後也只有 99.4185% 的分鐘列在 0.5 Wh 內 | 將原始量測殘差當品質資訊；模型內部平衡則要求數值容差內成立 |
| 五種策略在零電池時都相同 | 錯。分享與不分享的 PV 基準本來可不同 | 分開測試「無電池」與「不允許分享」的正確不變量 |
| PS/PSDT/LL 任一最佳解皆可比較帳單 | 錯。主目標有大量等價解，帳單會受求解器任意選解影響 | 先鎖主目標，再最小化帳單，最後最小化電池 throughput |
| 網路圖是五台變壓器且可做潮流 | 錯。圖中約 17 個 LV 變壓器；沒有線阻、相別、距離、電壓或背景負載 | 不聲稱做電壓潮流；只允許明示限制的 aggregate/transformer-headroom proxy |
| 年放電／充電 71.7% 是電池效率 | 不成立。這是量測邊界未知、含待機與控制行為的觀察比值 | 不把 0.717 直接塞成單向效率；論文基準維持每段 0.95，另作敏感度才可使用 |

## 兩篇論文的真正關係

- 兩篇均來自愛爾蘭 Dingle Peninsula 的 StoreNet 示範案，皆描述 20 戶、每戶 10 kWh／3.3 kW Sonnen 電池。
- 2022 方法論文使用 2019-07 至 2020-06 的內部量測，稱 9 戶有 2.4 kW PV。
- 2024 公開資料涵蓋 2020 年；實際有 10 戶出現 PV：H1、H2、H3、H4、H5、H7、H10、H11、H13、H17。資料論文稱 PV 為 2.0–2.2 kWp，README 則稱 2.4 kW。
- 2022 論文未公布典型日、9 個 PV 戶的身分、2019 下半年資料、SB-SC 商業控制器、完整 solver 設定或敏感度網格。因此 Bahloul Figure 5、Figure 6、Table I 與 Figure 7 都缺少數值級精確重現所需輸入。

## 本地發布資料完整性

本地 46 個發布檔（41 CSV、README、4 支作者程式）與 Figshare v1 的 46 個項目逐檔名稱、byte size 與官方 MD5 完全一致；本地沒有搬運損壞。另已保存 SHA-256 manifest。

這只證明「公開發布版完整」，不代表論文 Table 4 描述的 raw-to-processed 鏈完整。下列資料並未發布：battery-ID 原始檔、12 個原始月氣象檔、原始 figures 資料夾，以及可直接執行的原作者處理環境。

## 發布資料的已確認問題

1. Wh 檔已把缺值線性插值；H16 有一段 7,978 分鐘（約 5.5 天）的直線補值。這會在預測研究造成 look-ahead leakage。
2. H14 於 2020-12-11 結束；把其後日期補零會製造不存在的零負載。
3. H4_W 多出未記載的 `Unnamed: 6`，該欄有值期間 W/Wh consumption 關聯崩壞；問題也存在於官方檔，不是本地損壞。
4. 插值後 Wh 有 5,914 列同時充電與放電，其中 98.8% 落在 W availability 缺口；這些列不能當成真實控制動作。
5. 正確供需殘差應包含 `Feed-in`。所有住戶分鐘列中，只有 99.4185% 的絕對殘差小於 0.5 Wh，最大 90 Wh。
6. household timestamp 與 weather timestamp 均沒有 timezone metadata；住戶 PV 的季節位移支持「住戶為當地鐘錶時間、氣象近似 UTC」的推論，但已處理的一分鐘連續網格抹除了 DST 的重複／缺少分鐘。
7. 約 50 個日期的 PV 出力時間窗超出天文日長 0.5 小時以上，約占發布 PV 能量 16%；只能標記為異常，不能在沒有上游紀錄時武斷指定原因。
8. Trivedi Figure 7 程式對每日 Wh 取平均卻標成 kWh/day，數值少了 1.44 倍；相關係數近似不變，但 y 軸能量單位錯誤。

## 論文模型必須明示修正的地方

- 嚴格 `<`、`>` 改為 `<=`、`>=`；否則 binary=0 時形成 `0 < P < 0`。
- Equation (9) 的時間索引 `k` 改為求和索引 `t`。
- SoC 不直接把 kW×h 加到百分比；內部改用 kWh 儲能量。
- Equation (16) SH-BM 漏掉 PV-to-house；意圖版補回。
- 帳單目標補上 `Δt`，使單位成為 euro。
- 附錄把 `xi` 寫成 7%/day，但正文把它當戶間傳輸損失。基準只能把 0.07 視為無因次 transfer loss 假設，並另報 xi=0 敏感度。
- `P_SD` 沒有數值；基準設 0，不把 xi 誤當自放電。
- PS、PSDT、LL 以三階段詞典式最佳化固定退化解：主目標、帳單、throughput。

## 可復現性分級

| 層級 | 狀態 | 可接受說法 |
|---|---|---|
| 公開資料來源完整性 | 可完全驗證 | 本地 Figshare v1 發布檔 46/46 完整 |
| 作者 raw-to-processed pipeline | 不可完成 | 原始 battery-ID／monthly weather 未發布 |
| 五種策略的模型架構 | 可復現 | 論文意圖修正版，所有修正留痕 |
| 2020 公開資料的策略比較 | 可復現 | StoreNet 2020 independent replication |
| Bahloul Figure 5／Table I 數值級重現 | 不可證實 | 日期、9 PV 身分、ratio 實作缺失 |
| Bahloul Figure 6 年度數值級重現 | 不可完成 | 缺 2019-07 至 2019-12 且公開配置不同 |
| SB-SC 演算法級重現 | 不可完成 | 商業 IP 未公開；只能以量測輸出作近似 benchmark |
| 配電潮流／電壓研究 | 現有資料不足 | 只能做 aggregate peak/headroom proxy |

因此，本專案不以「靠挑日期讓節省率落在论文 ±3 個百分點」判定成功。成功標準是方程、單位、限制、資料品質、求解器狀態與差異歸因均可追溯。
